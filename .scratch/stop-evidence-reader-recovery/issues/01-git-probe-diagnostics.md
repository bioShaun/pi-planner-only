# 01: Git 采样失败提供具体原因

**What to build:** 当委派的 Git Evidence 采样失败时，Root 能直接从工具结果和持久记录看到具体失败阶段与原因，区分“环境不可探测”和“工作区仍在变化”，不再只得到 `stop-evidence sampling failed`。

**Blocked by:** None (can start immediately).

**Status:** implemented

**Parent:** [停止证据失败规格](../spec.md)，实施决策 §5，兼容要求 §7。

- [x] 从真实 GitRunner 结果到 Evidence、Execution 账本、委派结构化返回及文本展示贯通失败明细：采样阶段、固定 Git 操作、cwd、采样时间、退出码、超时/启动失败事实和有界错误摘要；未知值明确未知。
- [x] 覆盖 A_run、C_report、停止第一/第二样本及接受时采样；额外 worktree 的错误标出该根的 cwd。
- [x] 非 Git 目录、Git 无法启动、status 探测失败、超时和未分类错误有可靠依据时分别呈现；仅凭 code 128 不猜测具体原因，捕获异常不丢失原始原因。
- [x] 第一份停止样本失败而第二份正常、第二份失败、两份都失败均可从结果和账本查到实际失败阶段；最后一次采样不覆盖之前的失败。
- [x] 明细不得覆盖宿主原始终态、endedReason 或已有异常原因；工作区采样不一致与探测不完整分别展示。
- [x] 截断和敏感值遮蔽发生在持久化及展示边界；不保存原始凭据、环境转储或完整工具参数；输出上限和截断可见。
- [x] 保留既有状态和布尔字段的兼容性；旧账本无明细时展示“未记录”，不重造历史输出。
- [x] 使用现有 Evidence 与 Delegation/接受入口建立回归，验证实际工具返回、持久记录和文本，而非仅测试错误格式化 helper。至少用真实 Git 非仓库样本及可控失败 runner 覆盖上述分支。
- [x] 对应类型检查、受影响测试和错误诊断说明已更新，保留修复前失败及修复后通过证据。

**边界：** 本票交付错误可观测性，不改变能力分类、静止通过条件或 writer 启动策略；后两者分别由 02、04 负责。无需等待它们，也不等待 06 的查询工具即可通过委派结果演示本票。

**实施提示：** 若需局部整理采样结果构造，先在本票内部统一再接通错误明细；不扩展为更换采样后端的重构。
