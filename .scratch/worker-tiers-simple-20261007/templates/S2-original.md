Implement a per-repository read/write lock so several explorer children can run at once in one repository, while worker and validator stay exclusive.

Repo: /home/tcuni-claw/pi/pi-planner-only (pi extension, TypeScript run directly by node; tests are *.test.mjs).

Current behavior (delegate.ts): `ROLE_AGENTS` gives each role `exclusive: boolean` (worker/explorer/validator true, reviewer false). `runDelegation` (~line 466-480) resolves `lockKey` via `resolveLockKey` and calls `deps.locks.tryAcquire(lockKey)`; null → refusal "another worker/explorer/validator child is still running in repository ...". `CwdLocks` interface + `createCwdLocks()` ~lines 75-125. index.ts uses `session.locks.size` (handoff guard ~line 233, ~line 287).

Decided design:
1. Replace `exclusive: boolean` in ROLE_AGENTS with `lock: "exclusive" | "shared" | "none"`: worker "exclusive", validator "exclusive", explorer "shared", reviewer "none". Update the comment above ROLE_AGENTS accordingly (explorers only read project files; their report file is written per run under pi-subagents' artifact dir `outputs/<runId>/`, so explorers don't collide with each other).
2. `CwdLocks.tryAcquire(cwd: string, mode: "exclusive" | "shared" = "exclusive")`: exclusive succeeds only when nothing holds cwd; shared succeeds when no exclusive holder (any number of shared holders). Each successful acquire returns its own idempotent release. `isHeld(cwd)` = any holder. `held()` = distinct held cwds in first-acquisition order. `size` = number of distinct held cwds (so the handoff guard still blocks while any explorer runs). Keep default mode exclusive so existing callers/tests behave the same.
3. Refusal text: when blocked by an exclusive holder: "another worker/validator child is still running in repository X. ..."; when an exclusive request is blocked by shared holders: "N explorer child(ren) still running in repository X. ...". Keep the existing advice (wait, reviewer is read-only, pass a nested repository as cwd). You may add a small helper on CwdLocks (e.g. `holders(cwd)` returning { exclusive: boolean, shared: number }) if needed for the message.
4. Update user-facing text that states the old rule. Grep for it: the delegate tool description/prompt in index.ts (text like "worker, explorer, and validator run one at a time per repository (a second one is refused)"), README.md, README.zh-CN.md, CONTEXT.md decision "A child with bash or write holds its cwd until it ends". New rule wording, short: "worker and validator run alone per repository; explorers can run together but not alongside a worker or validator; a reviewer or another repository can run alongside." There are size caps on the Root prompt / tool text enforced by tests — keep wording short and make the tests pass without loosening any cap or assertion.
5. Tests (delegate.test.mjs, near the existing CwdLocks test ~line 466 and the refusal test ~line 365): two shared acquires on one cwd both succeed; exclusive refused while shared held, and succeeds after all shared released; shared refused while exclusive held; release idempotent (double release of one shared holder does not release another); size/held count distinct cwds. Via runDelegation: a running explorer does not block a second explorer in the same cwd but does block a worker (refusal names explorer); a running worker blocks an explorer. Look at how existing tests keep a child running (e.g. the abort test ~line 407 using a pending runDelegation) and reuse that pattern. Do not delete or weaken existing assertions; adjust only assertions whose expected text legitimately changed (e.g. refusal wording), and keep them as strict.
