# Kimi 单票探测实验记录（2026-09-07）

**目的：** 在 GLM-5.3-flash 无额度、插件已 `push` + `pi update` 到 v0.3.3 之后，用**当时用户 settings 里的 Kimi 配置**跑通一次 planner-only 单票，测量墙钟、token、费用，并观察 0.3.3 的 Worker / Oracle / Reviewer 边界是否生效。

**结论先看：** 这不是一次成功完成的 Task（没有 `planner_verdict` PASS）。实现本身在 2.2 分钟内提交；第一次 Reviewer 因脏树 `request_changes`；纠偏 Worker 死循环后被人工杀掉。票极小（+9 行），**不能**直接和 2026-09-06 的双票 GLM 70 分钟运行比「插件把 70 分钟变成了 10 分钟」。本文件记录过程与可核对数字，供后续分析。

**时区：** 会话时间戳为 UTC。北京时间 = UTC+8（例如 `00:03:07Z` = 08:03）。下文时间戳一律写 UTC，必要时括号给 CST。

## 7. 和 2026-09-06 GLM 运行的对照（不可直接比票）

对照来源：T-20260906-001，Worker `volcengine/glm-5-3-flash:high`，两张 hardening 票绑在一次实现里。插件当时还没有 0.3.3 的 bounded oracle / Worker 合同（那次跑完才提交 0.3.3）。

| | GLM 2026-09-06（双票大 diff） | Kimi 2026-09-07（+9 行 status） |
|---|---|---|
| 会话墙钟 | ~70 min 有效工作（13:49–15:21 含更早空闲则 92 min） | 到第一次 review **10.4 min**；含死循环 **25.2 min** 后被杀 |
| 首轮 Worker | 66 轮 / 37.7 min / $2.81 / 自审 `/code-review` 12 轮 | 33 轮 / 2.2 min / $0.15 / 无自审 |
| 报告-only Worker | 两轮共 ~13 轮 / $0.04（evidence 数组等） | 1 轮 2 turns / $0.01（canonical taskId） |
| Oracle | 2 次，含 `typecheck`+`npm test`+`e2e` | 4 次 bounded；未全量 npm test；3 次父进程没接到 |
| Reviewer | 16 轮 / 9.6 min / $0.40，大量 read/grep | 3 轮 / 1.2 min / $0.018，无 bash |
| 结束 | PASS（第二轮纠正 protectWriters） | **未结束**（request_changes → 死循环 → kill） |

**可归因于 0.3.3 协议、且在本次被观察到的：**

- 一张票，没有捆绑。
- Worker 合同存在；无 `/code-review` 自审。
- Oracle wrap `ORACLE_SUITE=bounded`；无全量套件（仍执行了 named 测试文件）。
- Reviewer 提示 packet-only；3 轮、无 bash。

**不能归因于「Kimi 比 GLM 快 10 倍」的：** 票大小差一个数量级。

**本次暴露、GLM 那轮没碰到的：**

1. `async=False` 的 Validator 被改写成 async 后，headless `bg_wait` 接不住，Root 连开 4 次 Oracle。
