# 第五步设计：真实委派里「方案明确的简单执行任务」占多少

日期：2026-10-07。状态：启动前写定，同日执行完毕，结果见 `findings.md`。执行时与本稿有两处不同：排除规则改为只排除对照试验的 child 运行（cwd 含 `worker-tiers`）；节省已低于 5% 的线，所以第 4 节结果判断没有执行。接 `docs/worker-tiers-evidence-2026-10-06.md` 第 6.9 节的「处置」。

## 1. 要回答的问题

1. 真实会话的 worker 委派里，「方案明确的简单执行任务」（下称 S 类）占多大比例，占 worker 费用多少。
2. Root 在委派前能不能认出 S 类：只看 task 原文的盲判，和看过结果后的判断一致吗。
3. 按第 6.9 节的价差（DeepSeek Flash 约为 Sonnet 的 28%），S 类全部换便宜模型能省多少，占总花费多少。

DeepSeek Flash 在真实 S 类任务上的超时率需要付费重放，不在本步；只有 1、2、3 都过线才另行设计。

## 2. 样本

- 来源：本机 `~/.pi/agent/sessions/*/` 下 Root 会话里所有 `delegate` 调用（2026-09-24 至 2026-10-07，均为 Lite 时期），以及 `subagent-artifacts/` 中对应的 child 产物。初步统计约 250 次 `role=worker`。
- 排除：基准/对照试验会话（bench、replay 运行目录），在清单中标出排除理由，不删除。
- 不连远端（om09/om36）。本机样本不足 60 条有效 worker 委派时再议。
- 每条委派记录：会话、项目目录、时间、cwd、状态、child 模型与 thinking、tokens、费用、轮数、耗时（来自 toolResult 首行 `[role/agent] status · model:thinking · tok · $ · turns · s`），task 全文，child 报告全文，以及 Root 之后的机械信号（见第 4 节）。

## 3. 盲判（只看 task 原文）

由 child 按下列规则给每条 worker task 打一个标签，看不到报告、费用和 Root 后续动作：

| 标签 | 含义 |
|---|---|
| S 方案明确的简单执行 | 要改什么、怎么改、验收是什么都已写清；worker 只需照做。包括：按详细规格写普通脚本、机械替换/改名、按给定文案改文档、按已有模式补测试、跑给定命令并修显然的错误 |
| C 需要推理 | 有需要 worker 自己设计或权衡的部分：未指定算法/接口、并发/状态/取消逻辑、多个约束同时成立、需要定位原因的 bug、开放式优化、视觉/设计质量 |
| U 无法判断 | task 依赖会话上下文、太短或指向外部文件，原文不足以判断 |

另记一个置信度（高/中/低）和一句理由。规则只看 task 本身，不看文件数和长度。

## 4. 结果判断（看过报告和 Root 后续）

由另一个 child 看 task、child 报告和 Root 此后到下一条用户消息之前的动作，给每条委派一个结果标签：

| 标签 | 含义 |
|---|---|
| OK | Root 直接接受（提交、进入下一项或向用户汇报），没有针对这次产出的修正 |
| FIX-CAP | 后续修正委派或 Root 亲自改动，原因是 worker 没做到 task 已写清的要求，或实现/推理错误 |
| FIX-SPEC | 修正原因是 task 遗漏、要求变化、reviewer 提出新要求或用户改主意 |
| FAIL-ENV | 超时、失败、拒绝、环境/凭据问题 |
| ? | 记录不足以判断 |

机械信号由脚本先算好供参考：同会话后续是否有同 cwd 的 worker 委派、其 task 是否引用前一次结果（「修」「上次」「仍」「fix」等）、Root 在下一条用户消息前是否自己调用 edit/write、是否有 reviewer 委派及其 P1/P2。

## 5. 判读（启动前写定）

- **占比**：S 类占有效 worker 委派 < 25%，或按第 6.9 节价差估算的节省 < 全部会话总花费（Root + child）的 5%：廉价档收益太小，分档问题结束，保持 Sonnet 单档。
- **可预判**：盲判为 S 的委派里，结果为 FIX-CAP 的比例；以及看结果后认为「其实是 C」的比例。两者合计 > 20%，或盲判 U 类 > 30%：Root 难以事先识别，同样结束。
- 以上都过线：设计 DeepSeek Flash 在真实 S 类任务上的重放（含超时率），另写设计，用户确认后执行。
- 历史 worker 多为 Luna 或 Sonnet，FIX-CAP 比例按模型分开报，不跨模型合并下结论。
- 根 agent 亲自抽查不少于 10% 的盲判和结果标签；抽查不一致率 > 20% 时，本步结论标为「不确定」。

## 6. 执行与预算

- 抽取脚本与清单：1 次 worker 委派。
- 盲判与结果判断：按批次委派，每批约 40 条，盲判与结果判断用不同 child，盲判 child 只拿到 task 文件。
- 预算：child 费用合计不超过 $5。全部离线读本机文件，不调用外部模型做重放。
- 原始会话文本不提交（含业务路径与内容），只提交脚本、汇总表和结论；逐条标签表提交，但 task 摘录截断到 200 字。
