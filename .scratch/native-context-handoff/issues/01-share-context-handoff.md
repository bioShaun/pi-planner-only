# 01：Native 共享上下文提醒和 handoff，并保护运行中的子任务

Status: needs-triage
Type: task
Source: ../spec.md

## 请求

用户要求把上下文提醒和 handoff 从 Lite 专属能力中拆出来，并补上对 Native 运行中子任务的检查，避免交接时中断任务。当前先提交设计，供 herdr 新 worktree 开展契约核对与后续实现；本提交不启用自动交接。详细方案与实施顺序见 [设计](../spec.md)。

## 预期行为

- Native 达到上下文阈值时也有提醒；可按有效 handoff 偏好准备交接，支持手动交接。
- 默认 handoff off、confirm 待用户提交、auto 自动提交，以及配置来源优先级保持不变。
- 通过宿主受支持接口确认本会话 Native 子任务已停止，再执行会话交接；不可只看 Lite 锁、累计费用、等待工具是否返回或局部缺失的完成事件。
- 活跃 async/workflow 子任务、停止未确认或查询失败时，禁止危险切换，明确说明原因并保留必要的交接材料；不取消任务来强行交接。
- 手动命令、模型 handoff 工具和 settled 延迟派发均经过保护，创建新会话前再次确认；检查后启动新任务的竞态不能漏过。
- 继续保存源模式（Native/Lite）、源模型/thinking 与完整简报；继承现有失败保留、取消和重试语义。新会话全局偏好不能覆盖源模式。
- 忙碌或状态未知时保留已接收的简报供手动重试；首版不增加自动轮询或完成后自动重试。
- 管理查询与 child 启动按操作语义区分；guide/status 返回、Root settled 和费用记录均不能单独证明无活动任务。

## 实施前核对

先确定宿主可用的活动/终态契约、父会话关联、workflow 汇总边界与切换竞态保护，再更新为 ready-for-agent。首个交付须列明实际接口、版本、调用顺序及支持限制；目前尚未证明宿主提供可靠活动查询和原子切换保护，不可将此票当作接口设计已完成。

本票包含为 handoff 调整 Native 工具可见性；其他 Native 工具注册与 supervisor 暴露问题由用户另行处理。

## 验收要求

- 新行为先失败测试后实现，保留可核对的红绿原始输出。
- 覆盖 Native/Lite/off 模式及 handoff off/confirm/auto，Native 手动与阈值触发行为。
- 故障注入：活跃任务、取消未确认、查询失败、延迟/重复终态、workflow 仍有子任务、检查与派发之间新任务启动；均不能提前创建新会话。
- 确认任务终止后按选定策略允许交接；其他父会话任务按明确关联契约处理，不误判。
- 保留并通过现有模型/thinking/简报交接回归，运行完整 release；宿主集成验证须覆盖真正相关的事件和查询，不能仅靠 mock 自述证明无中断。
