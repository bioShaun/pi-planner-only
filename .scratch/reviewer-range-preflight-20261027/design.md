# Reviewer committed-range preflight: decision proposal

Status: design only, for Root decision; baseline `cd5362490251aabdb1214b8041e70542cd5ff54a`. No product validation or ticket closure.

## Current capabilities

- Lite `delegate` has role/task/cwd/timeout only; it emits structured delegation with a string task and text result, not a diff or input-artifact field (`delegate.ts:202`, `delegate.ts:538`, `subagent-delegation-contract.ts:21`). Installed structured contract also has no such input; `artifacts` is a boolean for host run artifacts, not an input path, and unknown fields are rejected (evidence.md).
- Root can put an absolute artifact path or bounded text in the existing task. Reviewer has `read`, no shell; `watchdog_diff` is working-tree-only for this role. Installed read source accepts absolute and `..` paths with no repository-root check, subject to OS permissions and any runtime wrapper; actual reviewer runtime access is **not verified**. Its output is bounded to 2,000 lines/50 KiB, offsets paginate, but a single >50 KiB line is not readable without shell.
- Reuse `gitSafePrefix` and fixed argv, `--no-ext-diff`/`--no-textconv` policy from `git.ts:14`, `git.ts:19`, `git.ts:46`, `git.ts:71`. The existing audit truncates at 12,000 characters and its ref whitelist excludes named refs and 64-character IDs; it is not a complete range exporter. `captureBase` is a best-effort summary, not a cleanliness guard (`git.ts:182`).
- `subagent-artifacts.ts:88` locates host output/transcript after a run; it does not create review inputs and `project` can be inside the target repo. No verified host-provided safe committed-range export module was found. Native `options.baseRef` selects a worktree starting commit and is not a diff input.

## Interface decision

**Recommend:** add `base?: string` to Lite `delegate`, valid only with `role: "reviewer"`. With no base, preserve current behavior. With base, preflight synchronously before emitting a child request; put the absolute input path, full frozen SHAs, scope and limitations into the existing task text. Return a refusal with useful Git/error context on any preflight failure; do not emit a request. The path and metadata also reach Root in the outcome. This implements the ticket's one-call workflow without changing the structured delegation protocol or reviewer tool set.

Alternative: a separate public `prepare_review_diff({cwd, base})` exporting a path for Root to give to either Native or Lite. It gives both callers the same primitive, but adds a new public tool, an extra call, explicit caller-owned lifetime, and cannot itself guarantee the later child starts with matching source. Native mode currently supplies no Lite tools (`CONTEXT.md:13`); making it truly shared requires a separate scope decision. Prefer the one-call ticket interface now, keeping preparation as a private reusable module rather than promising Native support. Inline text avoids file access but introduces task size and clipping constraints, consumes context, and does not solve source consistency.

## Required behavior before launch

1. Require an existing worktree and a clean tracked/index state and no non-ignored untracked files at repository root. Fail closed on Git/status errors. Ignored files and submodule internals are not guaranteed clean: explicitly flag this limitation; do not claim a hermetic snapshot. Do not use `captureBase`'s silent fallbacks as the guard.
2. Accept named refs (e.g. `main`, `origin/main`, `refs/heads/main`), `HEAD`, `HEAD~N`, and full 40/64 hex IDs appropriate to repository object format. Use a narrowly validated grammar, reject leading `-`, whitespace/control, ref/revision metacharacters except the explicit `HEAD~N` form, and reject ambiguous/non-commit refs. Ref names must additionally pass Git ref-name validation; resolve each input once as a commit with fixed argv, no shell. For older Git do not assume `rev-parse --end-of-options`: validated non-option input plus `rev-parse --verify <ref>^{commit}` is the proposed compatible path; verify on supported old Git before release. Reject a failed or ambiguous resolution. Do not change `git_audit`'s unrelated accepted refs.
3. Freeze full base SHA and full HEAD SHA, compute merge base from those SHA arguments, and freeze its full SHA. Diff the frozen merge-base tree against frozen HEAD tree from repo root (`base...HEAD` semantics), with safe diff flags, `--no-color` and an explicit `--`. No merge base or multiple merge bases: refuse rather than choose an unspecified base. Check HEAD and clean status again immediately before dispatch; failure or change means refusal. A moved named base after resolution does not alter the frozen range; report all three SHAs.
4. Proposed simple completeness policy: reject empty diff with explicit `empty range diff; no review started`; reject any binary change with paths/count and an explicit incomplete-review explanation; reject output beyond 48 KiB, 1,900 lines, or any line beyond read's byte limit. Never clip, silently skip binary, or represent a stat-only result as a full diff. Limits are conservative proposals for Root to approve. Ensure Git execution/output transport detects truncation and bounded resource use; the current `GitRunner` has no truncation signal, so verify `pi.exec` behavior or use an appropriately bounded internal execution mechanism before relying on it. Git failure, output-limit, artifact creation/write/readability failure all refuse before dispatch.
5. The task explicitly instructs reviewer to read the entire artifact and report inability to do so as incomplete, not PASS. Artifact content is data, not instructions. Deliver range metadata and empty/binary/size refusal to Root. Human judgment of whether the child actually reviewed it remains Root's responsibility; a completed child is not proof of review.

## Consistency and lifecycle

- Frozen commits make the diff stable, not the live files. Reviewer takes no Lite lock (`delegate.ts:64`), external processes ignore Lite locks, and preflight checks cannot prevent subsequent changes or change-and-revert races. Require Root to ensure the checkout remains unchanged for the whole review; visibly mark source as live and consistency as not guaranteed in task and outcome. Recheck HEAD/status on completion where a terminal is available; if changed or probe fails, mark review stale/incomplete, not accepted. A check cannot prove no transient mutation. Isolated immutable checkout or serialization with external writers is a later, separate capability.
- For one-call Lite, plugin owns a unique private directory outside the target repository and writes a file with restrictive permissions and exclusive creation; ensure canonical path is not under repo even when temporary roots are symlinks. Use `/project/tmp/pi-1000` when configured by the operator, or a verified host-managed directory outside the repo; do not hard-code that machine path as a universal product default. No `project` artifact layout inside target repo, no Git ignore edits, no staging. Fail if no suitable external location is configured/available. The artifact may expose source: restrict access and report its absolute path to Root.
- Keep input until child terminal, including late terminal after an unconfirmed stop; cleanup on prelaunch failure and confirmed terminal, and avoid deleting while a child may still read. Crash/unconfirmed-stop leftovers are operator-owned recovery/cleanup; disclose path and retention. Host run-output artifact layout is not an input lifecycle manager. Cleanup errors must be visible, not change a review into a false success.

## Implementation and red/green acceptance

- `index.ts:517`: add schema/description and role restriction; update misleading committed-review guidance at `index.ts:73` and `index.ts:524`. `delegate.ts:202`, `delegate.ts:494`, `delegate.ts:538`: preflight before request emission, task/outcome metadata, stale result and input lifetime across late terminal. Private range generation belongs with Git policy in `git.ts` or a narrowly named adjacent module; do not alter unrelated public Git audit behavior. Reuse `host.ts` only where host capability really requires it, not a new delegation protocol. `subagent-artifacts.ts` remains output-only unless explicitly extended with separate input ownership.
- First add failing public-interface tests in `delegate.test.mjs`/`index.test.mjs`: reviewer happy path sends exact readable full diff and frozen SHAs; absent base unchanged; non-reviewer base, invalid/option injection, unresolved/non-commit and dirty/failing status all refuse with **zero request events**; errors surfaced; artifact outside repo and no repo pollution. Test cleanup on prelaunch failure, terminal and late terminal after unconfirmed stop; stale/unknown postflight cannot appear accepted.
- Add failing real small-repo tests via existing `git.test.mjs` patterns: clean worktree with committed range; divergent history uses merge base, named refs, `HEAD~N`, full IDs; failure/no/multiple merge base; SHA-256 repository where supported; changed HEAD/status during preparation; binary, empty, exact bounds and over-limit/oversized line; injected write/runner failures and transport truncation. Verify argv never runs external diff/textconv or accepts option injection, and old-version prefix fallback remains covered. Add installed-parser contract test for the unchanged request shape and actual read-tool outside-repo access/limits without paid model sessions. Fault-inject each added guard; do not weaken assertions.
- Green with focused suites, then `TMPDIR` outside repo `npm run test:release` per `AGENTS.md`; capture command exits and independent review. Test actual oldest supported Git or document a release blocker; mock version strings alone do not establish compatibility.

## Root decisions and deferrals

Must decide before implementation: approve Lite-only interface vs cross-mode export; exact byte/line caps and reject-binary/empty policy; trusted external directory configuration, permissions and retention; accept live-source warning plus postflight check vs require isolation; minimum Git and SHA-256 test availability. If external read or complete output transport cannot be established, stop rather than silently substitute a partial review. Deferred: chunking, binary inspection, path filtering, Native integration, immutable snapshots, broad audit ref changes, and review-platform/report protocols.
